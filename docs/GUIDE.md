# Руководство USBKey

[← Вернуться к проекту](../README.md)

Подробная документация для версии **0.3.4**: использование, хранение, сборка и обновление.

Нативное приложение с иконкой в строке состояния: зашифрованные пароли и произвольные токены на USB-флешке, SSH-агент Ed25519 и подпись Git. macOS 13+, Apple Silicon / Intel.

Меню строки состояния — отдельная неактивирующая панель, привязанная к экранным координатам значка. Она открывается под строкой меню в текущем Space, включая полноэкранные приложения; главное окно вызывается отдельно кнопкой «Настроить».

## Что работает

- Создание USB-ключа без форматирования и перезаписи других файлов.
- Ручная запись пароля, токена, многострочного текста; до 100 записей, до 65536 байт на значение.
- Генерация отдельных Ed25519-ключей внутри приложения; импорт существующего **OpenSSH Ed25519 без парольного шифрования**. RSA/ECDSA и расшифровка парольных OpenSSH-файлов не реализованы. Любой файл ключа можно сохранить как обычный текст, но SSH-агент использует только поддерживаемый Ed25519.
- Кнопка **«Ввести»** имитирует клавиатурный набор Unicode в поле, выбранное до открытия меню. Буфер обмена для секретов не используется. Требуется разрешение macOS «Универсальный доступ». Enter и Tab не отправляются; управляющие символы и многострочные значения не назначаются для быстрого ввода.
- Перед открытием списка записей, сохранением, удалением и назначением записи запрашивается Touch ID или пароль macOS через LocalAuthentication. Для каждого ввода подтверждение включено по умолчанию; его можно отключить в разделе «Устройство» → «Подтверждать каждый ввод через Touch ID / пароль». Тогда кнопка и комбинация вводят значение без проверки владельца; флешка и разблокированный сеанс по-прежнему обязательны. Системные запросы доступа Keychain могут появляться независимо от этого переключателя.
- Запись для быстрого ввода выбирается в основном окне кнопкой «Назначить для “Ввести”». Её ID хранится внутри зашифрованного хранилища на флешке; выбор сохраняется после отключения и перезапуска. Другие записи и SSH-ключи остаются в хранилище. Удаление назначенной записи сбрасывает привязку.
- Верхнее меню содержит четыре кнопки: «Ввести» с ключом, «Извлечь», «Настроить», «Выйти». Выбор носителя и записей находится в основном окне.
- Глобальная комбинация настраивается в разделе «Устройство». Нажмите поле сочетания и запишите своё (⌘ / ⌥ / ⌃ с клавишей; Esc отменяет запись). Комбинацию можно включать и выключать; по умолчанию выключена, предложено ⌥⌘K. Регистрация выполняется через Carbon RegisterEventHotKey, без перехвата всего потока клавиш. Конфликт регистрации показывается в интерфейсе.
- Ввод запоминает исходное приложение и отправляет ему отдельную пару key-down/key-up на каждый Unicode scalar. Стандартное Accessibility-поле не требуется: поддерживаются терминалы, Electron-редакторы и другие приложения с собственными полями. При переключении в другое приложение, блокировке, отзыве разрешения, нажатии модификатора или отключении носителя ввод останавливается. Переключение поля внутри того же приложения не блокируется — ввод направляется в его текущий клавиатурный фокус. Уже набранная часть остаётся в поле — при отмене удалите её вручную.
- Основное окно и меню используют собственную тёмную палитру, красный акцент, карточки записей и боковую навигацию.
- Собственный SSH-агент: закрытые ключи не добавляются в системный `ssh-agent` и не выдаются клиенту. Каждая подпись требует подтверждения в окне и Touch ID / пароля macOS. После подтверждения носитель проверяется повторно.
- SSH-агент принимает только Ed25519-запросы public-key аутентификации SSH, отказывает в произвольной подписи и изменении набора ключей. При блокировке сеанса отказывает в операциях.
- Подпись Git-коммитов помощником USBKey с предпросмотром Git-объекта. Старые токены версии 0.1 совместимы.
- Установщик размещает приложение в `/Applications` и LaunchAgent в `/Library/LaunchAgents/local.usbkey.autostart.plist`. Он запускает приложение в фоне для текущего вошедшего обычного пользователя. После нового входа запускается только значок. Настройка «Запускать … при входе» отключает фоновый запуск для текущего пользователя. Фоновый процесс не работает от root.

## Вход в macOS и аппаратная защита

**Пароль Mac можно сохранить как запись, но USBKey не является средством входа в macOS.** Меню работает в пользовательском сеансе после входа; оно недоступно для ввода пароля на экране loginwindow и в среде разблокировки FileVault. Приложение не меняет пароль аккаунта, PAM, authorization database, настройки FileVault или smart card.

Для штатного входа с физическим токеном macOS использует поддерживаемые smart card / PIV-механизмы. Файл на обычной USB-флешке не превращает её в CCID/PIV-устройство. Поддержка FileVault зависит от модели Mac и версии системы: [Apple — FileVault and smart cards](https://support.apple.com/en-ie/guide/deployment/dep806850525/1/web/1.0).

Поведение SSH-агента приближено к токену: клиент видит только открытый ключ и подпись, а закрытый ключ расшифровывается в памяти по запросу. **Но это не аппаратная некопируемость и не реализация FIDO2/WebAuthn/PIV.** UUID и серийный номер USB можно клонировать. Пользователь или вредоносная программа с контролем над Mac/процессом/Keychain может извлечь секреты. Для защиты закрытого ключа от самого хоста нужен настоящий аппаратный токен с защищённым чипом.

## Хранение

В корне флешки:

- `.usbkey-token.json`: основной Ed25519-ключ, зашифрованный AES-256-GCM, и открытые метаданные привязки.
- `.usbkey-secrets.enc`: названия, типы и значения дополнительных записей, целиком зашифрованные AES-256-GCM. ID токена и привязка устройства включены в authenticated data с отдельным доменом `USBKey/secrets/v1`.

Для каждого токена случайный 256-битный ключ шифрования хранится в Связке ключей macOS, без iCloud-синхронизации, с атрибутом `WhenUnlockedThisDeviceOnly`. Его нет на флешке. Проверяются UUID тома и SHA-256 серийного номера USB, если он предоставлен. Отсутствие серийного номера явно показано в интерфейсе. USB/Thunderbolt-мосты и некоторые APFS-тома, которые не прослеживаются в IOKit до USB-устройства, могут не определиться.

Открытые ключи, регистрации и резервные копии Git-конфигурации находятся в `~/Library/Application Support/USBKey`. Закрытые ключи и значения записей не записываются открытыми во временные файлы. Список названий/типов и открытых SSH-ключей после разблокировки остаётся в памяти до смены/отключения носителя или блокировки сеанса. Значения читаются с носителя при использовании. Никаких сетевых запросов или телеметрии приложение не отправляет.

Swift/CryptoKit не гарантируют немедленного обнуления всех копий данных в памяти. Потеря флешки, Keychain-записи или доступа к этому Mac означает потерю секретов. Экспорт, перенос на другой Mac и восстановление в этой версии не реализованы. Копирование токена само по себе не позволит открыть его на другом Mac; клонирование UUID/серийного номера на исходном Mac может обойти проверку носителя. Откат зашифрованного файла к старой копии не обнаруживается: защиты от rollback нет.

## Установка и использование

1. Установите `dist/USBKey-0.3.4.pkg`. Значок ключа должен появиться в строке состояния. Если автоматический запуск не разрешён macOS, откройте `/Applications/USBKey.app` вручную и проверьте «Объекты входа и расширения» в настройках системы.
2. Откройте «Настроить» → «Устройство». Выберите USB-том и создайте зашифрованный ключ.
3. В разделе «Хранилище» нажмите «Добавить запись…». Введите название, выберите тип и значение. Для SSH можно сгенерировать отдельный ключ или импортировать поддерживаемый файл.
4. В хранилище нажмите «Открыть», выберите однострочный пароль/токен и нажмите «Назначить для “Ввести”». Подтвердите запись привязки на флешку.
5. В разделе «Устройство» нажмите «Разрешить клавиатурный ввод…» и вручную включите установленное `/Applications/USBKey.app` в «Конфиденциальность и безопасность → Универсальный доступ». Начиная с 0.3.2 локальная сборка использует постоянный сертификат вместо ad-hoc подписи. При переходе с 0.3.1 и старее нужно один раз завершить USBKey, удалить старую строку из «Универсального доступа» кнопкой «−», добавить через «+» именно `/Applications/USBKey.app`, включить доступ, вернуться в USBKey и нажать «Перезапустить» в появившемся окне. Будущие сборки сохраняют ту же криптографическую идентичность, пока используется этот сертификат.
6. Выберите текстовое/парольное поле другого приложения, откройте значок USBKey и нажмите «Ввести». Подтвердите Touch ID / пароль macOS, если подтверждение включено. Приложение вернёт фокус исходному приложению и отправит ему клавиатурные события.
7. Для ввода без меню включите глобальную комбинацию в разделе «Устройство». Используется та же запись, назначенная этой флешке. Если подключено несколько зарегистрированных носителей, используется выбранный в основном окне; когда выбранный отключён и подключён ровно один другой, используется этот единственный носитель со своей собственной привязкой.
8. Закрытие большого окна оставляет значок, SSH-агент и включённую глобальную комбинацию работающими. «Выйти» завершает приложение и останавливает агент/регистрацию комбинации.

Клавиатурный ввод не зависит от роли или наличия Accessibility-поля. Он адресуется исходному процессу через Quartz `postToPid`; приложение само доставляет события своему текущему полю, терминалу или редактору. При открытии меню USBKey восстанавливает исходное приложение, даже если меню временно сделало активным сам USBKey. После глобальной комбинации программа ждёт отпускания её модификаторов. Буфер обмена не используется.

Перед вводом поставьте курсор в нужное место: USBKey не проверяет, является ли оно парольным полем. Обычное текстовое поле или терминал покажет вводимый секрет открыто. Некоторые приложения/защищённые системные экраны могут блокировать синтетические события — обход таких ограничений не реализован. Ни loginwindow, ни разблокировка FileVault не поддерживаются. Программа не нажимает Enter и не отправляет формы автоматически.

Хранилища 0.2 читаются без потери записей. После изменения хранилища версией 0.3 для его чтения используйте 0.3 или новее; откат на 0.2 не поддерживает новый внутренний формат привязки.

Новый SSH-ключ предпочтительнее повторного использования основного Git-ключа, но основной ключ тоже доступен агенту.

### SSH

Скопируйте открытый ключ выбранной SSH-записи и добавьте его в `~/.ssh/authorized_keys` на сервере. Закрытый ключ туда копировать не нужно.

Для одного подключения:

```sh
ssh -o IdentityAgent="$HOME/Library/Application Support/USBKey/agent.sock" user@server
```

Либо добавьте в нужный Host-блок `~/.ssh/config` (подставьте полный путь вашего пользователя):

```sshconfig
Host my-server
    HostName server.example.com
    User myuser
    IdentityAgent "/Users/YOUR_USER/Library/Application Support/USBKey/agent.sock"
    ForwardAgent no
```

Приложение должно работать, флешка — быть подключена. На каждый запрос подписи появится окно и системная проверка владельца. Проверять список открытых ключей можно так:

```sh
SSH_AUTH_SOCK="$HOME/Library/Application Support/USBKey/agent.sock" ssh-add -L
```

Агент не удостоверяет имя сервера: расширение session-bind и destination constraints пока не поддерживаются. Проверяйте имя и host fingerprint в SSH-клиенте. Не используйте agent forwarding. Извлечение флешки блокирует новые подписи; оно **не разрывает уже установленные SSH-сессии**. Другие методы аутентификации клиента (пароль, другие ключи) остаются доступными по его настройкам.

### Git

Задайте `user.name` и `user.email` в репозитории. Во вкладке «Git» выберите его папку. Настройки действуют только для этого репозитория: `gpg.format`, `gpg.ssh.program`, `user.signingkey`, `gpg.ssh.allowedSignersFile`, `commit.gpgsign`. Перед изменением сохраняется `git-backup-*.backup` в Application Support/USBKey. При ошибке записи приложение пытается вернуть прежние значения.

```sh
git commit
git log -1 --show-signature
git verify-commit HEAD
```

Для GitHub/GitLab добавьте открытый ключ как **signing key** отдельно от SSH-доступа. При смене `user.email` или пути к приложению настройте репозиторий заново. Чтобы временно отключить подпись:

```sh
git config --local commit.gpgsign false
```

Полное восстановление пяти параметров — по соответствующей резервной копии. Значения, которых ранее не было, удаляются через `git config --local --unset-all ИМЯ`. Владелец репозитория может отключить подпись; требование подписи всех коммитов нужно обеспечивать политикой сервера.

## Разрешение включено, но ввод запрещён

В разделе «Устройство» видны независимые состояния Quartz-отправки и Accessibility, а также путь запущенного приложения. Для ввода проверяется `CGPreflightPostEventAccess()`, а не доступ к чтению/управлению AX-элементами. Запрос выполняется через `CGRequestPostEventAccess()`.

При устаревшей записи TCC простой включённый переключатель может не соответствовать новой подписи. Приложение не переносит и не выдаёт себе это разрешение. При переходе со старой ad-hoc сборки удалите старую запись и добавьте установленную копию заново, как описано выше. Кнопка «Показать эту копию в Finder» помогает выбрать именно работающий bundle. Одновременный запуск нескольких копий с одним bundle ID блокируется.

После обнаруженного изменения разрешений приложение предлагает окно «Перезапустить» / «Позже». После возврата из настроек разрешений, открытых через USBKey, это окно предлагается и при старом кэшированном статусе TCC. В «Устройстве» также есть постоянная кнопка «Перезапустить». Перезапуск выполняет подписанный помощник в отдельной сессии: он ждёт завершения старого процесса и открывает новую копию. Это работает и для приложения, запущенного через LaunchAgent. Кнопка тестового ввода удалена.

## Сборка

Нужны macOS 13+, Xcode/Command Line Tools, Swift 5.9+, Python 3 (для локальной подписи), Git 2.34+ и системный OpenSSH с `ssh-keygen -Y`.

Сначала один раз создайте постоянную локальную идентичность:

```sh
python3 scripts/setup-local-signing.py
```

Скрипт создаёт сертификат Code Signing и изолированную связку в `~/Library/Application Support/USBKey Build Signing` (директория 0700). Закрытый ключ не попадает в проект; временные PEM/P12 удаляются. Пароль отдельной связки хранится в файле 0600 в той же защищённой директории. Скрипт восстанавливает прежний список пользовательских связок и **не меняет настройки доверия сертификатам**. Не удаляйте эту директорию между сборками. Самоподписанный сертификат нужен для постоянства идентичности, а не для обхода Gatekeeper или TCC.

```sh
./scripts/build.sh                  # текущая архитектура
ARCHS=universal ./scripts/build.sh  # Apple Silicon + Intel
```

Результаты: `dist/USBKey.app`, `dist/USBKey-0.3.4.pkg`. PKG содержит приложение, подписанный помощник жизненного цикла, LaunchAgent и скрипты preinstall/postinstall для текущего console user. Скрипт сборки не устанавливает пакет и не изменяет системные настройки разработчика.

По умолчанию используется постоянная локальная подпись `USBKey Local Development` с требованием, привязанным к сертификату и bundle ID, а не к хешу бинарника. Автоматического отката на ad-hoc нет. PKG не подписан Developer ID и не нотариализован. Для распространения:

```sh
APP_SIGN_IDENTITY='Developer ID Application: YOUR NAME (TEAMID)' \
INSTALLER_SIGN_IDENTITY='Developer ID Installer: YOUR NAME (TEAMID)' \
ARCHS=universal ./scripts/build.sh
xcrun notarytool submit dist/USBKey-0.3.4.pkg --keychain-profile YOUR_PROFILE --wait
xcrun stapler staple dist/USBKey-0.3.4.pkg
```

Без Developer ID и нотариализации Gatekeeper может блокировать распространённую через интернет сборку. При смене локального сертификата на Developer ID понадобится повторное разрешение TCC и, возможно, подтверждение доступа Keychain. Для изолированных временных ad-hoc экспериментов можно явно задать `ALLOW_ADHOC_SIGNING=1`, если локальная идентичность не настроена; такие сборки не сохраняют TCC-идентичность при изменении бинарника.

## Удаление

Сначала отключите USBKey в настроенных Git-репозиториях и в `~/.ssh/config`. Выключите фоновый запуск в приложении и завершите его. Для удаления общесистемного LaunchAgent администратор может выполнить:

```sh
launchctl bootout "gui/$(id -u)/local.usbkey.autostart"
sudo rm /Library/LaunchAgents/local.usbkey.autostart.plist
```

Затем переместите `/Applications/USBKey.app` в Корзину. Файлы на флешке и Keychain при удалении приложения сохраняются. Удаление записи `USBKey — UUID` в Keychain сделает все связанные секреты невосстановимыми. Сохраните открытые ключи для проверки старых подписей.

## Проверки

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/module-cache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/module-cache" \
swift test --disable-sandbox --build-system native
```

Тесты используют исключительно временные ключи/файлы, не изменяют реальные флешки, Keychain, настройки входа или серверы. Интеграционный тест открывает временный локальный Unix-сокет и проверяет его настоящим `ssh-add -L`; sandbox, запрещающий `bind`, нужно отключить для этого теста.

35 тестов проходят. Дополнительно проверяются сохранение/сброс назначенной записи, чтение старого массива 0.2, целостность Unicode и суррогатных пар, ровно один Unicode scalar на событие, выбор исходного приложения без зависимости от AX-полей, запрет Enter/Tab/управляющих символов, отмена отправки следующих фрагментов при потере фокуса/носителя и валидация комбинаций. Тесты ввода используют фиктивный отправитель и не набирают текст в ваши приложения. Проверяются также AES-GCM/привязка/подмена данных, хранение записей и совместимость токена 0.1, импорт OpenSSH, SSH-agent wire format и реальная криптографическая подпись, отказ в произвольной подписи и отмене, права сокета/конфликт экземпляров, совместимость SSHSIG с OpenSSH и реальным Git commit-объектом, резервирование Git-настроек. Проверку реального USB, Touch ID/Keychain, подключения к вашему серверу, реального клавиатурного ввода/переключения фокуса/работы глобальной комбинации и установки с автоматическим запуском следует выполнить на целевом Mac.

Технические источники: [Git](https://git-scm.com/docs/git-config), [SSH Agent RFC 9987](https://www.rfc-editor.org/rfc/rfc9987.html), [OpenSSH private key format](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL.key), [Apple AES.GCM](https://developer.apple.com/documentation/cryptokit/aes/gcm), [Apple Quartz Unicode keyboard events](https://developer.apple.com/documentation/coregraphics/cgevent/keyboardsetunicodestring(stringlength:unicodestring:)), [Apple Accessibility permission](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions), [Apple smart cards and FileVault](https://support.apple.com/en-ie/guide/deployment/dep806850525/1/web/1.0).

Стабильность идентичности: [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements), [Apple Code Signing Tasks](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html), [Quartz post-event permission](https://developer.apple.com/documentation/coregraphics/cgpreflightposteventaccess()).

Проверка стабильности подписи после сборки: `python3 scripts/verify-signing-continuity.py dist/USBKey.app`. Скрипт меняет временную копию bundle, подписывает её той же идентичностью и проверяет: Code Directory Hash изменился, designated requirement остался тем же. Установленное приложение и TCC не меняются.

## Обновление поверх старой версии

Установите новый PKG поверх существующей версии. До замены файлов preinstall запускает подписанный helper от имени текущего GUI-пользователя: он корректно завершает запущенные экземпляры USBKey, включая старую вручную открытую копию. Если они не закрываются за 5 секунд, helper завершает их принудительно; при неудаче установка прерывается до замены приложения. После установки новая версия открывается в строке состояния. Единоразовый запуск после обновления не включает отключённый пользователем автозапуск на будущие входы.

Обновление не удаляет UserDefaults, Application Support/USBKey, Keychain, токены и записи на USB. Привязка ввода и комбинация сохраняются. Подпись остаётся привязанной к тому же локальному сертификату. Скрипты не сбрасывают TCC и не выдают разрешения: при первом переходе со старой ad-hoc подписи доступ нужно подтвердить вручную в macOS. Просто скачивание PKG ничего не устанавливает — требуется запустить установку.

Дополнительные тесты проверяют переходы разрешений, отсутствие повторных диалогов после «Позже», возврат из настроек с кэшированным статусом и изоляцию процесса перезапуска от группы старого LaunchAgent. Полный сценарий установки с завершением пользовательского приложения проверяется при установке пакета на целевом Mac; автоматические тесты не закрывают ваши приложения.

Кнопка «Извлечь» использует штатный NSWorkspace unmountAndEjectDevice без принудительного отключения. Извлекается активный зарегистрированный носитель либо единственная подключённая USB-флешка. При неоднозначности между несколькими устройствами выбор не угадывается. Носитель повторно проверяется перед операцией; занятый диск возвращает ошибку, которую меню показывает пользователю. Автоматические тесты не извлекают реальные диски.
